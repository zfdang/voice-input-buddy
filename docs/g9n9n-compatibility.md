# G9N9N 语音支持与按键映射限制

更新日期：2026-10-28。适用产品：Voice Input Buddy 的 macOS 版本。

## 核心结论 (TL;DR)

1. **普通按键不可用**：G9N9N 遥控器发送的按键信息不符合苹果 macOS 的规范要求。设备自身描述符声明每个报告包含 2 个按键槽位（2 字节），但实测单独按键和松开时只发送了 1 字节。macOS 底层发现数据包长度与描述符不一致后直接拦截丢弃，应用完全收不到事件，因此**不支持普通单键映射**。
2. **语音功能完全正常**：遥控器的语音键和麦克风走的是独立的蓝牙 ATVV 语音协议，不受普通按键 HID 报文问题影响，语音输入可稳定使用。
3. **实验性双键 Enter**：同时按下两个按键（如 OK＋方向键）时刚好填满 2 字节，数据符合 macOS 长度要求并成功递交给应用。应用已支持在日常输入中用 **OK＋任意方向键** 触发单次 Enter（回车），需在设置中开启自定义按键并由应用独占设备。

## 功能支持矩阵

| 功能 | 支持状态 | 说明与使用前提 |
| --- | --- | --- |
| 蓝牙连接与 ATVV 协商 | **支持** | 正常配对与能力握手 |
| 遥控器麦克风与语音键 | **支持** | 走独立 ATVV 服务，语音输入已实测可用 |
| 音频解码与虚拟麦克风输出 | **支持** | 16 kHz IMA ADPCM，自动路由至 Voice Input Buddy Mic |
| 普通单键映射（方向/确定/返回等） | **不支持** | 报文短于描述符要求，被 macOS 底层拦截丢弃，应用收不到 |
| 普通按键长按与连发 | **不支持** | 缺失松开报文，无法维护按键按下与释放状态 |
| OK＋任意方向键 | **实验性 Enter** | 完整双键报文能送达应用；开启映射且应用独占时发送一次 Enter |
| 向导初始按键检测 | **支持（双键绕过）** | 通过双键组合（OK+上、返回+上）生成完整报文以通过向导检测 |

## 操作指南

### 1. 首次向导中如何通过按键检查
由于单键无法送达应用，向导中的按键检测需使用双键完成：
1. **初始 OK 验证**：同时按下 **OK（确定）＋上方向键**，检测到输入后全部松开（不要按语音键）。
2. **后续三键测试**：先同时按 **OK＋上**，松开；再同时按 **返回＋上**，松开。累计识别到 3 个不同按键即可继续后续语音配置。

> **提示**：向导双键仅用于满足初次设置的检查门禁，不代表日常普通单键映射功能可用。

### 2. 日常如何使用双键 Enter
1. 在应用的“按键映射”页面选中 G9N9N，开启“自定义按键”，确保已授予“输入监控”和“辅助功能”权限，设备处于连接且被应用独占状态。
2. 在任意文本框中，短按 **OK＋上/下/左/右任意一键** 即可发送一次 Enter（如在文本编辑器中换行）。
3. 尽量短按；因为遥控器不发松开报文，长按可能造成重复触发。

## 技术原理与抓包证据

### 为什么被 macOS 丢弃？
* **HID 描述符要求**：G9N9N 的 Report 1 描述符声明了两个 8 位按键索引槽位，即每次按键通知应包含 **2 字节** 数据。
* **实际发送报文**：
  * 单独按下上键：设备只发了 `03`（**1 字节**）。
  * 松开按键：设备只发了 `00`（**1 字节**）。
* **系统处理逻辑**：Apple 开源的 [IOHIDElementPrivate 源码](https://github.com/apple-oss-distributions/IOHIDFamily/blob/main/IOHIDFamily/IOHIDElementPrivate.cpp) 中明确规定，当固定长度报告的实际长度小于描述符定义时丢弃该报文。因此单键和松开事件在进入应用层之前就被 macOS 丢弃。
* **双键为什么行**：同时按下“返回+上键”时，设备发送了 `03 0B`（**2 字节**），刚好占满两个槽位。macOS 判定长度合规，加上 Report ID `01` 后封装为 `01 03 0B` 交付给应用。
* **为什么软件无法修复**：丢包发生在操作系统内核/驱动层，应用在用户态根本拿不到短包，无法在未收到的短包后补零；CoreBluetooth 也未向应用暴露该设备的 HID 服务。
